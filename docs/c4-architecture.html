HR Desk — C4 Architecture

C4 model (levels 1–4) of the hr-ticketing-system repo dated 2026-10-05: a React SPA that talks to a FastAPI backend, which persists everything in a Supabase project (Postgres + Storage) using the service-role key. Branch initial-frontend.

People interact with the SPA directly from the browser; the SPA calls the API (VITE_API_URL, default http://localhost:8000/api); only the backend touches Supabase (RLS blocks all client-side access).

Runtime view — flow of an agent reply (illustrates how the layers cooperate)

sequenceDiagram
  autonumber
  participant B as Agent browser (SPA)
  participant S as store.js cache
  participant A as FastAPI /api
  participant P as Supabase Postgres
  B->>S: addReply(TKT-101, {authorId, text})
  S->>A: POST /api/tickets/TKT-101/replies
  A->>P: SELECT ticket WHERE ref/uuid
  A->>P: SELECT user (role derived server-side)
  A->>P: INSERT reply (author_id, author_role, body)
  A->>P: UPDATE ticket (first_reply_at once, Open to In Progress)
  A-->>S: 200 full ticket (ticket_out, camelCase)
  S->>S: upsert into cache + notify
  S-->>B: subscribed hooks re-render

Rules worth remembering

  • Contract: endpoint shapes mirror src/data/store.js 1:1 (camelCase), so UI code never changed when the mock store was replaced by HTTP calls.
  • Single writer: only the backend touches Supabase, with the service_role key (bypasses RLS). Never put that key in the frontend.
  • Business rules live in the API, not the DB and not the UI: agent reply stamps firstReplyAt once; assigning an unanswered ticket auto-posts the pickup reply; employee replies flip to Waiting on Employee; Resolved stamps resolvedAt; Closed records closedBy; reopening clears both.
  • Identity of a ticket for the UI is the generated reference TKT-<n> (starts at TKT-101); raw Postgres uuid is carried as uuid for admin/debug.
  • Writes return the full ticket including its thread turns, so the SPA updates its cache in one round-trip.
  • Errors: 404 unknown ticket, 413 file > 5 MB, 422 validation / unknown user, 400 vs 502 mapped from PostgREST error codes (23xxx = constraint).
